  - Collections: users, complaints, collections, facilities, ai_scans, datasets

  - CI/CD: GitHub Actions + GitHub Pages (legacy, now using Vercel)

AI MODEL:
  - Architecture: EfficientNetV2-S (22M parameters)
  - Training: TensorFlow/Keras on Google Colab T4 GPU (6-8 hours)
  - Dataset: ~70,000 images from 5 Kaggle datasets
  - Inference: TensorFlow.js in browser (offline capable)
  - Fallback: Demo/simulation mode if model file not found

4. AUTHENTICATION SYSTEM
================================================================================

The app uses a DUAL authentication approach:

A) EMAIL/PASSWORD (Primary)
   - Frontend calls POST /api/auth/login with {email, password}
   - Backend queries Firestore: users collection where email+password match
   - On success: user object returned, stored in localStorage under key
     "wastewise_session"
   - Passwords stored in PLAIN TEXT in Firestore (⚠️ security concern)

   DEMO BYPASS ACCOUNTS (hardcoded, work even when Firebase is offline):
     admin@wastewise.com   / admin123   → role: admin
     citizen@wastewise.com / citizen123 → role: citizen
     worker@wastewise.com  / worker123  → role: worker

B) SOCIAL LOGIN (Google + Phone OTP) — via Firebase Client SDK
   - Google: signInWithPopup(auth, googleProvider)
   - Phone: RecaptchaVerifier + signInWithPhoneNumber
   - After Firebase auth, frontend calls POST /api/auth/social-login
     with {uid, name, email, phone, provider}
   - Backend creates or retrieves user in Firestore

C) REGISTRATION
   - POST /api/auth/register with {name, email, password, role, area}
   - Checks for duplicate email
   - Saves to Firestore users collection
   - Returns user (without password)
   - User stored in localStorage session

SESSION MANAGEMENT (src/lib/auth.ts):
   - getSession()    → reads localStorage → returns User | null
   - logout()        → removes localStorage key
   - updateSession() → overwrites localStorage entry
   - User interface: {_id, id, name, email, role, complianceScore,
                       rewardPoints, avatar, area, createdAt}

ROUTE PROTECTION:
   - <ProtectedPage> component wraps protected routes
   - Reads session; if null → redirects to /login
   - UserProp helper passes the session user as a prop to child pages

8. AI WASTE CLASSIFIER (src/pages/AIDetectPage.tsx)
================================================================================

What it does:
  Classifies waste images into 3 categories:
    - GREEN_BIN  → Organic/Biodegradable (food scraps, leaves)
    - BLUE_BIN   → Recyclable (plastic, glass, metal, paper)
    - RED_BIN    → Hazardous (batteries, chemicals, non-recyclables)

How it works:
  1. Page loads → dynamically imports @tensorflow/tfjs + WebGL backend
  2. Tries to load model from /public/tfjs_model/model.json
  3. If model found → real inference using EfficientNetV2-S
  4. If model NOT found → Demo mode (random result with fake 82-97% confidence)

Input modes:
  - File Upload (JPG/PNG up to 10MB)
  - Live Camera (getUserMedia, environment-facing, 640×480)
  - Capture photo from camera → analyze

Inference pipeline (real model):
  img → tf.browser.fromPixels() → resizeBilinear([300,300])
      → expandDims(0) → cast('float32') → model.predict()
      → argmax → CLASSES[maxIdx] → confidence %

User Feedback (AutoML loop):
  After result shown, user can confirm or correct the classification.
  Correction data is POSTed to /api/datasets for model improvement.
  Admin can trigger retraining from AdminDashboard.

Model Training:
  - Notebook: Smart_Waste_Trainer.ipynb (runs on Google Colab)
  - Direct link to Colab from Admin Dashboard
  - Dataset: ~70,000 images, 5 Kaggle sources
  - Output: TF.js model files saved to /public/tfjs_model/

10. COMPLIANCE SCORING SYSTEM
================================================================================

How scores change (server-side, automatic):
  +5  pts → Citizen files a new complaint
  +10 pts → Complaint moves to 'in_progress'
  +20 pts → Worker marks a collection as 'completed'
  -15 pts → Complaint filed AGAINST a citizen (not fully implemented)
  -30 pts → Repeated violation (not fully implemented)

Score displayed:
  - In sidebar header (all roles)
  - In CitizenDashboard as StatCard + Progress bar
  - In RewardsPage with full breakdown
  - Badges based on score:
    >= 80 → "Green Citizen" (Award icon)
    >= 50 → "On Track" (TrendingUp icon)
    <  50 → "Needs Attention" (AlertTriangle icon)

Leaderboard:
  Top 10 users ordered by complianceScore desc from Firestore.
  Shown in CitizenDashboard and RewardsPage.
  Current user's row is highlighted.

14. KNOWN ISSUES & LIMITATIONS
================================================================================

1. PASSWORDS STORED IN PLAIN TEXT
   Firestore stores raw password strings. No bcrypt/hashing used.
   This is a major security vulnerability for production.

2. NO ROLE-BASED ROUTE ENFORCEMENT
   /users route is only "admin" logically, but any logged-in user can
   navigate there manually. No server-side role check on frontend routes.

3. TRAINING PAGE HAS NO MODULES
   mockTrainings is set to [] — Training Center shows no courses.
   The quiz system is built but has no content to display.

4. MONGOOSE MODELS NOT USED
   server/models/*.js files define MongoDB/Mongoose schemas, but the app
   uses Firestore. These files are dead code.

5. MAP IS SIMULATED
   Both FacilitiesPage and WorkerDashboard use a static Google Maps
   screenshot URL as background image. No real interactive map.
   Google Maps API key is not configured.

6. AI MODEL MAY NOT BE DEPLOYED
   If /public/tfjs_model/model.json is missing, the app falls back to
   demo mode (random results). The model must be manually exported from
   Colab and placed in the public folder.

7. INSPECTION REPORTS NOT PERSISTED
   ChampionDashboard's "Submit Inspection Report" only shows a toast
   notification — it does NOT call any backend API.

8. TRAINING SCORE NOT TRACKED IN BACKEND
   CitizenDashboard hardcodes trainingsCompleted = 0 with a comment
   saying backend tracking is not yet implemented.

9. LOGINPAGE AND AUTHPAGE DUPLICATE
   There are two separate login UI files (LoginPage.tsx = 24KB,
   AuthPage.tsx = 12KB). The router sends /login to LoginPage and
   /auth redirects to /login. AuthPage seems to be a refactored version
   not actively used via routing.
